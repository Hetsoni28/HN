2. TECHNOLOGY STACK & ARCHITECTURAL HIGHLIGHTS
================================================================================
• Framework & Runtime:
  - Next.js 16.3.6 with Turbopack bundler for instantaneous HMR & build execution.
  - React 19.2.0:
    * Server Components by default for zero client JS bundle overhead.
    * Strict adherence to React 19 effects rules (no synchronous setState in effects).
    * `useSyncExternalStore` for SSR-safe client storage (sessionStorage/localStorage).
  - Node.js 22 LTS environment.

• Styling & Design System:
  - Tailwind CSS v4 via `@tailwindcss/postcss`.
  - CSS variables for theme tokens, borders, and glassmorphic backdrops.
  - Custom scrollbar styling, responsive typography clamp calculations.

• Animations & Interactivity:
  - Framer Motion 12 (`framer-motion`):
    * Viewport-triggered scroll reveals (`FadeIn`, `motion.div`).
    * Smooth interactive sliders (Before/After comparison).
    * Dynamic animated counters and interactive ROI calculators.

• Content Management (Sanity Studio v6):
  - Embedded Studio route at `/studio` for visual in-browser content management.
  - `@sanity/client`, `@sanity/image-url`, `next-sanity`.
  - Dual-mode data fetching: If Sanity credentials are not present, the entire website
    seamlessly renders rich, typed static fallback content from `lib/content.ts`
    with zero downtime, zero blank states, and zero console errors.

• Utilities & Media Generation:
  - PDF Export: `jspdf` for generating downloadable client project briefs & estimates.
  - Image Capture: `html-to-image` for capturing client quotes and shareable graphics.
  - Video Automation: `fluent-ffmpeg` and `puppeteer` available for asset processing.
  - Transactional Emails: `resend` SDK integrated in Server Actions.
  - Form & Schema Validation: `zod` schema parsing for all user submissions.

6. CMS DATA SCHEMAS & HYBRID FALLBACK ARCHITECTURE
================================================================================
The project implements a resilient Dual-Layer Hybrid Data Architecture:

1. Live Sanity CMS Layer (`sanity/schemaTypes/`):
   - `service.ts`: Defines title, slug, icon, shortDescription, whatWeProvide, features, tech stack.
   - `project.ts`: Defines title, slug, category, industry, challenge, approach, solution, metrics.
   - `blogPost.ts`: Defines title, slug, publishedAt, author, excerpt, mainImage, body content.
   - `testimonial.ts`: Defines client name, role, company, quote, rating, project badge.
   - `faq.ts`: Defines question, answer, category, orderIndex.
   - `siteSettings.ts`: Defines primary phone, email, address, announcement banner text.

2. Zero-Downtime Fallback Layer (`lib/content.ts`):
   - If Sanity environment variables (`NEXT_PUBLIC_SANITY_PROJECT_ID`) are absent, invalid, or
     if Sanity API encounters network latency, the application automatically falls back to 
     typed static records in `lib/content.ts`.
   - Ensures the website never crashes, never shows empty pages, and builds completely offline.

8. SECURITY, RATE LIMITING & FORM PIPELINES
================================================================================
• Rate Limiting (`lib/security.ts`):
  - Sliding-window in-memory IP rate limiter protecting Server Actions (`/contact`, `/referral`).
  - Limits excessive requests (e.g. max 5 requests per 15-minute window per IP).
• Data Validation:
  - All form submissions are parsed and sanitized using strict Zod schemas on the server side.
• External Link Protection:
  - Standardized `ExternalLink` atom automatically injects `rel="noopener noreferrer"`.
• Content Security:
  - CSP and security headers pre-configured in Next.js configuration and proxy middleware.
